# FakeNews AI

FakeNews AI is a full-stack machine-learning and AI web application that analyses news headlines or articles and predicts whether the submitted content is likely to be **fake** or **real**.

The project combines a supervised machine-learning model with an AI explanation layer. The machine-learning model makes the actual prediction, while Gemini AI explains the result in plain English for the user.

The application includes authentication, saved analysis history, dashboard statistics, machine-learning insights, responsive design, and a deployed online version.

## Project Overview

FakeNews AI allows users to paste a news headline or article into the application. The backend processes the text using a trained machine-learning model and returns:

* Prediction: fake or real
* Confidence score
* Risk level
* Input type
* AI-generated explanation
* Responsible-use warning

The prediction is generated by a scikit-learn Logistic Regression model trained on labelled fake and real news datasets. The text is converted into numerical features using TF-IDF vectorisation.

Gemini AI is then used to generate a clear explanation of the machine-learning result. This makes the output easier for non-technical users to understand.

The application is intended as an educational AI and machine-learning project. It should not be used as final proof that an article is true or false.

## Machine-Learning Workflow

The machine-learning part of the project follows these steps:

1. Load labelled fake and real news datasets.
2. Clean the text data.
3. Remove duplicate and invalid records.
4. Convert text into numerical features using TF-IDF vectorisation.
5. Train a Logistic Regression classifier.
6. Evaluate the model using test data.
7. Save the trained model as a `.pkl` file.
8. Load the saved model inside the FastAPI backend.
9. Use the model to classify new user-submitted text.

The trained model file is stored at:

```text
backend/models/fake_news_model.pkl
```

This file is required for both local and deployed predictions.

## Responsible Use

FakeNews AI is an educational machine-learning tool. It provides a risk estimate, not final proof.

The application should be used to support critical thinking, not to replace human judgement. Users should verify important claims using trusted sources, official websites, and multiple reputable news organisations.

Potential limitations include:

* The model may learn source-specific writing patterns.
* The model may not understand the full factual context of an article.
* New misinformation styles may differ from the training data.
* High confidence does not guarantee factual correctness.
* AI-generated explanations may simplify the reasoning.

## Supabase Setup

The application uses Supabase for authentication and saving user analysis history.

Create a table called `checks` in the Supabase SQL editor:

```sql
create table if not exists public.checks (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  input_text text not null,
  input_type text not null,
  prediction text not null,
  confidence double precision not null,
  confidence_percentage text not null,
  risk_level text not null,
  explanation text not null,
  created_at timestamptz not null default now()
);

alter table public.checks enable row level security;

create policy "Users can insert their own checks"
on public.checks
for insert
to authenticated
with check (auth.uid() = user_id);

create policy "Users can view their own checks"
on public.checks
for select
to authenticated
using (auth.uid() = user_id);

create policy "Users can delete their own checks"
on public.checks
for delete
to authenticated
using (auth.uid() = user_id);
```

Supabase Auth redirect URLs should include:

```text
http://localhost:3000/**
https://fake-news-identifier-omega.vercel.app/**
```

The Supabase Site URL should be:

```text
https://fake-news-identifier-omega.vercel.app
```

## Authentication and Security

The app uses Supabase Auth for user login and registration.

Security-related behaviour:

* Protected pages require login.
* Session data is stored using browser session storage.
* Closing the browser tab ends the session.
* Users are automatically logged out after 5 minutes of inactivity.
* Saved analysis records are protected by Supabase Row Level Security.
* Users can only view, insert, and delete their own checks.

Protected routes:

```text
/analyse
/dashboard
/history
/ml-insights
/account
```

Public routes:

```text
/
/login
/register
```
